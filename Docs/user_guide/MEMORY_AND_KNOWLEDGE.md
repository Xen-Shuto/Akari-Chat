# 記憶と知識

[ユーザーガイドに戻る](USER_GUIDE.md)

## 記憶の種類

「記憶・知識」のサブメニューから開きます。

| 種類 | 主な使い道 |
| --- | --- |
| キャラクター指示 | 人柄・口調・基本ルール |
| コアメモリ | 会話の土台にする短い重要情報 |
| 永続記憶 | 継続して保持する人物・関係・経験の情報 |
| 日記 | 日付ごとの記録 |
| エピソード | 出来事をまとめた記録 |
| 夢日記 | 内省や指針の記録 |
| エンティティ記憶 | 人物・物・概念など対象別の記録 |
| 創作ノート・分析ノート | 創作や調査・考察の文章 |
| 知識資料 | 会話・検索で参照する資料 |
| 短期メモ | 一時的に覚えておきたい内容 |
| 選択中の話題 | 現在使うワーキングメモリ |

全資料が毎回全文送信されるわけではありません。直接送る設定と、検索して抜粋を送る仕組みがあります。

## 本文を編集する

1. 対象の種類を開きます。
2. 日記・エピソードなどでは年月とエントリを選びます。
3. 本文を編集し、保存します。
4. 完了表示を確認し、必要なら検索索引も更新します。

コアメモリ・永続記憶・短期メモなどは対応する本文を直接開きます。更新前のバックアップと、外部変更との競合確認を行って保存します。

読み込み後の変更が通知された場合は、編集中の本文を控え、現在の内容を再読込して比較します。「未保存を破棄」などの操作は編集中の変更を捨てます。更新前のバックアップから戻す場合も、内容を確認して保存し直します。

## 話題を切り替える

「話題の切替・作成」でワーキングメモリのスロットを作り、本文を確認して切り替えます。「選択中の話題」で現在の本文を編集できます。

複数の話題を作っても、全本文を同時送信するわけではありません。

### 話題の自動選択

同じ画面の「話題の自動選択」は初期OFFで、押した時点で保存します。自動選択を使う場合は手動選択をmainに戻します。main以外の手動選択は優先されます。

活動記録の研究・目標・問いと関連付けた話題が候補です。通常会話では活動タイトルとの一致などを使います。話題を作っただけで、自由に全話題から推測して選ぶ仕組みではありません。

「言い換えによる選択」は独立した初期OFF設定です。自動選択もONで、起動済み検索モデルと更新済み索引があり、候補が明確な場合に意味の近さを使います。曖昧・未準備の場合は採用しません。送信内訳で選択理由を確認します。

### 休眠・復帰

選択した話題を休眠させると、自動選択などの候補から外せます。現在選択中の話題は先に切り替えてから休眠します。休眠中の話題は復帰してから選択します。本文の物理削除ではありません。

「自動休眠」は初期OFF、標準30日です。夜間の時間帯を使いますが、夜間の記憶生成の有効化とは独立しています。main、手動選択中、進行中の活動に関連する話題などは保護します。未使用の判定にはアプリが記録した送信試行の時刻・本文版を使い、単純なファイル更新日だけでは決めません。

## 会話から記憶を作る

1. 「会話から記憶を作る」で対象会話を確認します。
2. ローカル会話モデルを準備し、「草案を生成」を実行します。
3. 要約・日付などを読み、必要なら修正します。
4. 「確認した内容を記憶に保存」で反映します。

画像の中身や途中停止した回答は対象になりません。会話の記録日時と話題中の出来事の日付が異なる場合は、保存する日付を確認します。

選択した草案から「振り分け案を生成」すると、種類別の追記案を作れます。元草案・分類先の案・保存済み本文はそれぞれ別です。

## AI更新案を確認する

「AI更新案」で対象・元資料・変更後本文・理由を読み、修正して承認・保存するか見送ります。

生成後に元資料が変わると古い案を適用できない場合があります。会話の編集後は、関連草案や保存済み記憶に古い情報が残っていないかも確認してください。

## 会話後の自動処理

| 設定 | 内容 | 注意 |
| --- | --- | --- |
| 会話後の自動草案 | 有効化後の完了回答5件ごとに草案を作成 | 初期OFF。古い全ログの一括処理ではありません |
| 自動分類 | 草案から種類別の追記案を作成 | 分類先の保存とは別です |
| 自動エピソード保存 | 新しく作成した対象草案を保存 | 初期OFF。手動・過去の草案を一括承認しません |
| 分類先の自動保存 | 新しい対象の分類案を保存 | 初期OFF。エピソード保存と独立です |
| 保存後の索引更新 | 保存済み本文の索引更新を予約 | 「ルーム設定 → 記憶索引」で設定。初期OFF |

生成にはローカル会話モデルが必要です。競合・中断・結果未確認では後続を停止し、確認を求めます。本文保存と索引反映の成功は別なので、両方の履歴を確認します。

夜間整理は [自律行動と予約](AUTONOMY_AND_SCHEDULES.md) を参照してください。

## キーワード検索と意味検索

「検索」で、記憶・過去会話・知識などの対象と方式を選びます。

- **キーワード検索**：文字一致で探します。言い換えや表記ゆれには限界があります。
- **意味検索**：埋め込みモデルと索引で意味が近い抜粋を探します。出典も読んで内容を確認します。

手動検索の結果が次の会話に自動添付されるわけではありません。会話での自動検索はルームと検索モデルの設定に従います。NexusArkの共通設定は自動では取り込みません。

意味検索は [検索モデルの設定](MODELS_AND_SETTINGS.md) 後、「ルーム設定 → 記憶索引」で索引を作成します。本文・会話を追加した後も更新が必要です。保存後の自動更新は起動済み検索モデルを使い、追加でモデルを起動する設定ではありません。

警告・未索引の件数・出典を確認してください。順位や類似度は正しさを保証しません。初回索引作成は資料量に応じて時間がかかります。進捗を確認し、必要なら停止してから再開できます。

## 実際に送る記憶を確認する

「アプリ設定 → 動作の確認 → 会話に使う記憶を確認」で次回送信予定と直近の送信内訳を見ます。

コア・短期メモ・選択中の話題・期間内のエピソード・夢の指針などは各設定と対象条件に従います。永続記憶・日記が存在するだけで無条件に全文送信するわけではありません。

文字数はトークン数でも、画像・全会話を含む総入力サイズでもありません。直近の記録は今回の起動中の送信内訳であり、生成成功の証拠ではありません。

## 整理・統合などの高度な機能

- **旧主記憶の整理**：旧 `memory_main.txt` の見出しから永続記憶・日記への追記案を作ります。原本は削除しません。
- **睡眠時の整理**：エピソード・夢・永続記憶・短期メモなどの整理案を作り、AI更新案で確認します。
- **日記アーカイブ・圧縮**：期間・元資料を確認して要約・整理に進みます。複数ファイル集約では入力元と保存先を確認します。
- **RAG・意味統合**：検索補正や意味の近いエンティティの統合候補を扱います。候補作成と自動適用は別設定です。
- **エンティティの統合履歴・休眠**：結果や状態を確認し、必要なら復帰します。対象本文を読んで実行してください。

自動整理には初期OFFの追加設定があります。対象範囲と履歴を確認し、一つずつ有効にしてください。
