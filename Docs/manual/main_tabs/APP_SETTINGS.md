# アプリ設定タブ

[詳細マニュアルに戻る](../MANUAL.md#メニュー別リファレンス)

開く場所：右ペインの「共通設定 → アプリ設定」。

## このメニューでできること

アプリ全体の会話/検索モデル、標準の会話API、音楽検索、共通の接続先、診断、外観を設定します。ルーム独自の上書きがある項目は、そのルームの指定を優先します。

## 各タブの案内

### 会話モデル

共通の接続方式、外部APIの認証・モデル、ローカルGGUFと起動条件。

#### 会話モデルを準備する

ローカルならGGUFとllama-serverを選び、必要なmmproj/MTP、コンテキストやGPUレイヤーを確認して保存し、「モデルを起動」を押します。起動条件を変えた場合はモデルを停止して起動し直します。

「会話モデル」で接続方式を選びます。外部APIを選ぶとキー・モデルの設定が表示されます。未設定時の初期選択はGemini APIです。対応先ではモデル一覧を取得できます。通常は各ルームがこれを継承し、独自接続のルームは「ルーム設定」で設定します。キーを空欄保存しても同じ接続の保存済みキーは保持します。

#### ローカル設定の変更が効く時点

- GGUF・mmproj・MTP・コンテキスト・GPUレイヤー・追加起動引数：モデルの停止/起動後。
- Temperature・Top-P・通常会話の最大生成tokens・送信履歴数・思考モード：保存後に開始する生成。対応モデルや接続先の制約は残ります。
- 会話API：保存後の新しい生成に実効接続を使用。生成中/会話待ちの保存は拒否する場合があります。
- 検索モデル：設定保存、プロセスの起動、ルーム索引更新を分けて確認。
- 外観：選択時はプレビュー、保存後に実効値として反映。

自律・研究購読・会話後の記憶生成/分類・夜間整理・日記アーカイブの文章生成は、ルームの会話API接続を使います。埋め込み・検索・索引はローカルです。Discord自動返信、URL監視の任意要約、アイテム/画像プロンプト案などの補助生成は引き続きローカル用経路です。

#### ローカルGGUF一覧の更新

会話モデルと記憶検索モデルのドロップダウン右側に「一覧の再取得」があります。アプリを起動したまま追加・削除したGGUFを反映します。会話はModels/LLM、記憶検索はModels/embeddingsを再帰走査します。再取得では未保存の入力と選択値を維持し、保存・起動はしません。一覧にない既存パスも「一覧外」として選択を保持します。

### 外部連携

Google認証、Gatewayサーバー・HTTPS・トークン等。

#### 外部接続・外観を整える

X/Discordのアカウントはここに共通登録しません。「ルーム別設定 → 外部接続」でルーム内に登録します。Google認証とGatewayの共通基盤はここ、カレンダーID・ルーム利用許可はルーム側です。

外観の基本値を保存すると、共通を使っているルームに反映します。ルーム側で上書きした項目はその指定を使います。テーマを選んだだけでなく、保存後の表示も確認してください。

#### Google認証とGatewayの共通設定

Googleの「この接続を利用可能にする」、OAuthクライアントID/秘密鍵、手動アクセストークン/更新トークン、認証情報の消去、OAuth認証URL作成を扱います。認証を用意した後、各ルームで利用許可とカレンダーIDを保存します。X/Discordの認証は共通へ登録しません。

| Gateway項目 | 初期値・範囲 | 意味・保存条件 |
| --- | --- | --- |
| 待受先 | このPCのみ（127.0.0.1）/全インターフェース（0.0.0.0） | 後者はHTTPS必須。OS/ルーター設定は自動変更しない |
| ポート | 初期0、0〜65535 | 0は空きポートを自動選択。利用URLは起動後の状態表示を確認 |
| HTTPS証明書のフルパス | 未設定 | 秘密鍵と両方指定。公開用接続には有効な証明書が必要 |
| HTTPS秘密鍵のフルパス | 未設定 | 秘密情報として保管 |
| 接続トークンを再発行 | 通常OFF | 新規発行時だけ表示。旧トークンは無効になる |

設定変更はGateway停止中に行います。「設定を保存」と「Gatewayを起動」は別操作です。停止操作はGatewayを止め、アプリ全体は止めません。ルームのアクセス許可・会話・イベント保存は別タブで設定します。

#### 画像生成の方式別既定値・参照画像

画像生成そのものは未設定時「無効」です。ローカルを選んだ場合の既定URLは `http://127.0.0.1:7861/sdapi/v1/txt2img`、サンプラーEuler a、25Steps、CFG7.0で、肯定前置/後置・否定プロンプトは空です。

Gemini/OpenAI互換等ではモデルIDとキーを準備します。モデルID未指定のまま接続可能と判断しません。接続先URL変更時には古いキーの扱いも確認します。画像生成の設定は会話APIとは独立しています。

参照画像は方式・モデルで対応判定します。現行ではGeminiのimage系やOpenAI互換の対応するgpt-image等に限定した判定があり、ローカルtxt2imgへ画像を選べば自動でimg2imgになる仕組みではありません。完成画像は8MiB以内のPNG/JPEG/静止WebP、各辺8192以下かつ総画素16,777,216以下の検査があります。

#### 画像生成の受付・完了・タイムアウト

画像生成ツールのokは「予約の受付成功」で、画像の完成ではありません。会話の応答終了後に別処理で生成先へ送信します。

「アプリ設定 → Web・画像生成」の生成APIの待機上限は30〜1800秒の整数。初期値はローカル600秒、外部180秒です。初回モデル読込に時間が必要な場合は増やせます。生成API応答の待機上限であり、結果URLからの画像取得など後続処理まで含めた全体秒数の厳密保証ではありません。

タイムアウトは「結果未確認」として保持します。生成先で処理が続く可能性があるため、自動再送はしません。画面では「タイムアウト（結果未確認）」を表示し、AIから受け付けたジョブは状態確認のポーリングでも通知します。

通常の次の会話には、同じルームで直近24時間にAIが受け付けた最大3件の状態・結果を渡します。元の画像プロンプトや認証情報は含めません。これは会話開始時点の状況で、途中に状態が変わることがあります。過去の会話の再生成には後からの状況を自動挿入しません。画像生成の履歴でも状態や経過時間を確認できます。

### 動作の確認

ログ、ツール結果、送信記憶の内訳、生成計測など。

AIが「保存した」と話すだけでは実行成功とは限りません。「動作の確認」でツールの状態・結果や送信内訳を確認します。

### 外観

基本テーマ、アクセント、フォント、文字サイズ、会話行間。

#### 外観の全項目（共通・ルーム共通の仕様）

| 項目 | 選択肢 | 共通の初期値 | 意味・変更の影響 |
| --- | --- | --- | --- |
| 画面テーマ | あかり/ニュートラルダーク/ライト | あかり | 背景・パネル・文字・通知などの配色を切替 |
| アクセント色 | テーマ標準/緑/青/紫/橙 | テーマ標準 | 操作や強調の色を切替。全色を個別指定する機能ではない |
| UIフォント | 標準（游ゴシック）/UDゴシック/明朝 | 標準 | 見出し・操作部等の基本フォント |
| 会話フォント | UIと同じ/標準/UDゴシック/明朝 | UIと同じ | 会話本文の字体 |
| 全体の文字サイズ | 小/標準/大 | 標準 | UI倍率0.9/1/1.15 |
| 会話本文の文字サイズ | 12/14/16/18/20px | 14px | 会話本文の基準サイズ |
| 会話の行間 | 狭め/標準/広め | 標準 | 行高倍率1.6/1.95/2.2 |

ルーム側には各項目に「共通を使う」があります。変更した項目だけルームを優先します。フォントは端末にあるものを使い、なければ代替します。ダウンロードはしません。

選択時のプレビューと保存は別です。「全項目を共通に戻す」「あかりの初期値に戻す」も編集欄を戻す操作なので、反映には保存します。ニュートラルダーク/ライトは青系の標準アクセントと赤系の通知です。
