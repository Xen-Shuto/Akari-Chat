# 記憶・知識タブ

[詳細マニュアルに戻る](../MANUAL.md#メニュー別リファレンス)

開く場所：右ペインの「ルーム別設定 → 記憶・知識」。

## このメニューでできること

キャラクターの指示、各種の記憶・ノート・知識資料を読み書きし、検索・整理・AI更新案の反映を行います。操作対象はROOMで選んだルームです。

## 各タブの案内

### 検索

記憶・知識・過去会話などをキーワード/意味検索。

#### 検索の項目

| 項目 | 意味・変更時の動作 | 初期値 | 入力条件・選択肢 |
| --- | --- | --- | --- |
| 検索する言葉 | 調べたい言葉や内容。キーワード方式では文字の一致、意味方式では内容の近さを使います。 | 既存値/対象に従う | 画面入力 200文字まで |
| 検索方式 | 文字一致か意味の近さかを選びます。意味方式には検索モデルと索引が必要です。 | 既存値/対象に従う | 選択肢：キーワード、意味検索 |
| 検索対象 | 記憶・会話・知識等の検索対象範囲を選びます。他ルームの全文を混ぜる指定ではありません。 | 既存値/対象に従う | 選択肢：すべて、記憶、過去会話、知識資料 |

操作ボタン：

| 操作 | 作用・確認点 |
| --- | --- |
| 検索 | 対象の一覧・資料・履歴・表示を確認または切り替えます。表示だけで原本保存が完了したことにはなりません。 |
| 検索モデル・索引の準備を確認 | 対象の一覧・資料・履歴・表示を確認または切り替えます。表示だけで原本保存が完了したことにはなりません。 |

#### 直接送信と検索の違い

| 資料 | 会話での主な扱い |
| --- | --- |
| キャラクター指示 | 基本の指示文として構築 |
| コアメモリ | send_core_memoryが有効なら送信。未指定の既定はtrue |
| 短期メモ | send_notepadが有効なら送信。未指定の既定はtrue |
| ワーキングメモリ | 手動/今回の自動選択で決まった一つの話題を送信。他の全話題を全文送信しない |
| エピソード・夢 | 設定・期間・対象条件に合う記録を利用 |
| 永続記憶・日記 | 原本として保持。存在するだけで全文送信やコア反映を自動実行しない |
| 知識・会話ログ等 | 検索対象に含め、採用された抜粋を利用 |

直接文脈の主な保存先はSystemPrompt.txt、core_memory.txt、notes/notepad.md、notes/working_memoriesです。永続記憶の原本はmemory/memory_identity.txt、日記の原本はmemory/memory_diary.txtです。取り込み後のデータ種類によりDBや各ファイルを併用します。

### RAG・意味統合

| 項目 | 意味・変更時の動作 | 初期値 | 入力条件・選択肢 |
| --- | --- | --- | --- |

| 新しさ補正の半減期（日） | 最近の情報を求める検索で、新しさ補正の半減に用いる日数。小さいほど古い情報の優先度が早く下がります。記憶の削除期限ではありません。 | 90日 | 1〜3650 |

| 確認した案を統合 | 選択中の対象へこの操作を行います。対象・内容・確認欄・履歴を確認し、競合/結果未確認の場合は再実行前に実体を調べます。 |

#### 検索補正と意味統合の既定値

RAG補正OFF・半減期90日、夜間意味統合OFF、自動適用OFF、類似度下限0.97です。半減期は1〜3650日、統合下限は0.9〜1。共通検索モデルの下限0.45とは別設定です。

RAG補正は語句パターンによるtechnical/personal/recent等の分類と日付を使います。技術寄りの照会では知識、個人的な照会では記憶/会話を補正します。最近の照会では日付に応じた新しさの重みを付けます。古い資料を期限切れとして削除するものではありません。

意味統合では候補確認→案作成→原本と案を確認→適用を区別します。類似度が高いだけで二つの人物や出来事が同一とは限らないので、本文を比較します。

### コアメモリ

本文編集の共通項目は[知識資料](#知識資料)にまとめています。

#### コア反映・日記アーカイブ

永続記憶をコアへ反映する専用操作は、全文を要約せず対応節へ入れる確認待ち案を作ります。短く圧縮する汎用草案とは別で、生成しただけではコアは更新されません。

日記アーカイブは「この日まで」を含む対象の抽出、要約生成、退避計画、承認後の保存、退避後の日記整理案という段階を持ちます。要約だけができた状態と原本更新完了を混同しないでください。

| この案を見送る | 対象の一覧・資料・履歴・表示を確認または切り替えます。表示だけで原本保存が完了したことにはなりません。 |
| 案の読み込みを解除 | 対象の一覧・資料・履歴・表示を確認または切り替えます。表示だけで原本保存が完了したことにはなりません。 |

タブは1行の横スクロールです。見えない項目は横へ移動して選びます。

## 記憶を編集する

1. 対象のタブを開きます。
2. 日記などは年月とエントリ、資料などは対象ファイルを選びます。コアメモリ・永続記憶・短期メモは決まった本文を開きます。
3. 本文を編集して保存します。
4. 完了表示を確認します。意味検索にも反映する場合は「ルーム設定 → 記憶索引」の更新状態を確認します。

別の画面や外部エディターで同じ資料が変わった場合は、現在の本文を読み直して差分を確認します。未保存の破棄は、編集中の内容を捨てる操作です。

## 検索・草案・自動処理の使い分け

「検索」で見つけた結果は、それだけで次の会話へ添付されません。会話中の自動想起は別設定です。意味検索には共通の検索モデルとルームの索引が必要です。

AI草案を作った後は「AI更新案」などで内容を確認して反映します。自動草案・分類・保存・索引更新はそれぞれ独立した設定です。一つを有効にしても他が全部有効になるわけではありません。

## 注意すること

保存された記憶すべてを毎回全文送るわけではありません。直接送信と検索抜粋を区別し、「アプリ設定 → 動作の確認」で送信内訳を確認します。整理・統合前には対象と保存先を確認し、原本のバックアップも保管してください。

## 保存するボタンと、その場で保存する切替

通常の本文編集は保存ボタンで確定します。一方、「話題の自動選択」「言い換えによる選択」「自動草案」「草案後の自動分類」等の切替ボタンは、その操作で状態を保存する経路です。表示プレビューを変えるだけの操作とは異なります。

バックアップ本文を編集欄へ読み込む操作は、原本をその時点で復元しません。読み込んだ内容を確認して保存します。エンティティ統合の取り消しは両原本の状態を扱う別操作なので、単なる本文の読み込みと混同しないでください。
