# 自律行動タブ

[詳細マニュアルに戻る](../MANUAL.md#メニュー別リファレンス)

開く場所：右ペインの「ルーム別設定 → 自律行動」。

## このメニューでできること

会話していない間のキャラの活動、目的・研究・問い、実行の許可と履歴を管理します。睡眠時の記憶整理とは別の仕組みです。

### 実行設定

定期実行・睡眠時間・クールダウンを設定し、内部状態を確認。

#### 最初に試す

1. ルームの会話API設定を確認します。共通設定の接続を使うか、ルーム独自の接続を保存します。ローカル接続の場合は会話モデルを起動します。
2. 「活動記録」に目的や関心、取り組みたい内容を用意します。
3. 「実行設定」で許可と上限を確認し、まず手動実行で動作を確かめます。
4. 「実行履歴」と会話欄を見て、実行結果・発言・更新案を確認します。
5. 定期実行したい場合だけ有効化し、間隔などを保存します。

通常画面では定期実行の有効化、睡眠時間、クールダウンを設定します。初期は定期OFF。未設定時は5分ごとに動機等の開始条件を確認し、1回300秒、日次回数と自律側の出力tokens上限は指定しません。保存済みの設定は保持します。待機時間が過ぎれば必ず発言するわけではありません。

#### 会話との順序と結果の保存

通常会話を優先し、会話中・会話待ちに新しい自律処理を始めません。自律処理の途中に発言した場合は、その処理を完了してから会話を開始します。

通常の自律や行動予約で生成した発言は会話欄にもAIとして表示・保存します。架空のユーザー発言は追加しません。夜間整理など内部処理の出力をすべて流す仕組みではありません。

記憶更新案を作る許可と、保存の承認は別です。実際のツール結果や保存状態を確認してください。段階ごとの文脈は必要な情報で組み直しますが、上限なしの生成ではありません。

#### 止めたいとき・動かないとき

定期自律をOFFにしても、研究購読・夜間整理・URL監視・会話後の記憶処理が一括で停止するわけではありません。それぞれの設定を確認します。

実行されない場合は、モデル、保管状態、日次上限、待機中会話、実行中処理、結果未確認、動機の条件を確認します。結果未確認を成功扱いにして再送しないでください。

睡眠時間は「自律行動 → 実行設定」で管理します。初期OFF、標準00:00〜07:00（JST）です。睡眠中は定期自律と短いお知らせを待機させます。手動実行・明示的な行動予約・通常会話は可能です。夜間整理の対象と自動保存は「ルーム設定 → 夜間の記憶整理」で別途設定します。

#### 動機判定の読み方

動機判定ONの場合、退屈・好奇心・目標達成・関係性の各レベルから最大のものを開始判断に使います。未解決の問いや進行中目標の優先度・進捗、選択した活動などが材料になります。

開始にはクールダウンが0以下かつ最大レベルが閾値以上であることが必要です。直前の充足や同じ動機の連続、似た報告・停滞の補正でレベルが下がる場合があります。経過時間が同じでも毎回同じ活動にはなりません。未設定時は動機判定が有効で、クールダウン30分、退屈度最大まで120分です。

感情はモデルの自己申告に由来する内部情報です。Arousal、共鳴、関係性、ユーザー感情の推定は人の感情の測定値ではありません。対応する独立設定をONにした場合のみ補正に利用します。

#### 内部状態リセットの対象

リセット前に画面の対象一覧を読みます。会話・記憶・ツール監査を全削除する操作ではなく、動機や感情等の内部状態を初期化します。「未解決の問いも保管する」は追加対象です。保管は原本・履歴を残す扱いで、消去ではありません。

リセット後も定期設定・権限・接続先・実行上限は別に確認します。興味の文章をプロンプトに加えただけで自動実行が始まるわけではありません。

#### キャラクターの睡眠時間

「実行設定」で睡眠時間の有効化、開始・終了（JST）を保存します。初期OFF、標準00:00〜07:00です。日付をまたげますが同時刻は指定できません。睡眠中は通常の定期自律と短いアプリ内お知らせを待機し、夜間の記憶整理を優先します。手紙・タイマー・URL通知、手動実行と行動予約はこの抑制の対象外です。会話を妨げず、実行中の整理は終了してから次の会話へ進みます。

睡眠の有効化だけでは記憶整理を開始しません。「ルーム設定 → 夜間の記憶整理」で対象と自動実行を有効にします。保存は確認待ちが基本で、夜間案の自動保存許可は別です。既存の有効なお知らせ待機時間を優先して引き継ぎ、それがなければ有効な旧夜間時刻を使います。保存するまでは元の設定を書き換えません。

#### 実行履歴・行動の過程・結果未確認

実行受付、待機、生成中、完了、失敗、中止、結果未確認を区別します。行動の過程の注記や手順候補を編集しても、過去のツールを実行し直しません。

再起動などで途中の結果が不明な処理はunknownとして残す場合があります。「確認済み」は保存先・履歴等を調べたことの記録で、成功への強制変更や再実行ではありません。未確認が解消するまで背景処理が待機することがあります。
