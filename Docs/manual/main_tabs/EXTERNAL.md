# 外部接続タブ

[詳細マニュアルに戻る](../MANUAL.md#メニュー別リファレンス)

開く場所：右ペインの「ルーム別設定 → 外部接続」。

## このメニューでできること

このルームで利用する外部アカウント、参照・投稿先、利用許可を設定し、参照結果や送信案を管理します。会話LLMの外部APIとは別です。

## 各タブの案内

### X / Twitter

投稿方針の要約と投稿ガイドラインは、Xの投稿ツールを提示するときにAIへ渡します。自動投稿は既定でOFFです。ONにしても、自動送信には外部接続の書き込み権限が必要です。公式APIの引用・返信は既定で承認待ちになります。X Premiumは手動設定で、ONにするとあかり側の通常投稿の文字数制限を緩和します。接続先による制限は引き続き適用されます。

「Discordに承認依頼を通知」は既定でOFFです。設定したルームのDiscordメインチャンネルへ通知し、ボタンはユーザID本人のみ操作できます。ボタンの受信にはGateway常時接続が必要です。「詳細」を押すと、本人だけに投稿本文と添付画像が表示されます。長文は全文をテキストファイルで表示します。確認したらDiscordの通知で「承認して投稿」または「却下」を選びます。

接続方式や認証情報は「設定」タブで管理します。設定を保存した後、公式APIでは「API接続テスト」、Cookieでは「セッション状態確認」で、認証中のアカウントを確認できます。

「投稿・承認待ち」タブの「承認待ちを更新」で、このルームの投稿案を表示します。一覧のIDを選ぶと本文と添付画像を確認できます。送信先と内容の確認にチェックを入れて「承認して投稿」を押すか、「却下」を選びます。「投稿履歴」では投稿済み・却下・失敗・結果未確認などの送信記録を確認できます。

1アカウントの登録・認証、利用条件・参照/送信案。

| --- | --- | --- |

| 接続中のユーザー名 | Cookieのログイン先として確認できたユーザー名 | Cookie取り込み時に確認して自動設定。読取専用 |

| 更新トークン | アクセストークン更新用の値 | 接続方式に応じて必要。秘密情報 |
| 対象アカウントの数値ユーザーID | X APIで対象を特定する数値ID | 表示名や@名と区別する |

#### XのCookie取り込み

**Cookie取り込みはXの非公式な接続方式で、利用は推奨しません。公式APIの利用を推奨します。Cookie方式の利用によりアカウントが制限・凍結される可能性があります。利用は自己責任となり、アカウントの凍結などによる不利益について、Akari-Chatの開発者は責任を負いかねます。**

1. ROOMを選び、「外部接続 → X / Twitter」を開きます。
2. 接続方式で「Cookie」を選び、「設定を保存」を押します。必要なら利用許可もONにします。
3. 自分のXアカウントから明示的に書き出したCookie JSONを貼り付けるか、JSONファイルを選びます。
4. 「Cookieを取り込む」を押します。Xへの読み取り専用のログイン先確認を行い、確認できた場合だけルーム内へ暗号化保存します。取り込み自体は投稿しません。
5. 成功すると入力したCookieは画面から消去され、「Cookie保存済み」と接続中のユーザー名が表示されます。他ルームとの登録重複も表示します。

対応形式はCookieの配列（NexusArkのCookie JSON形式）か、cookies配列を含むJSONです。上限256KiB、300件。X/twitter.comのCookieだけを取り込み、他サイトのCookieとlocalStorageは保存しません。有効なログインCookieが必要です。取り込み時に有効期限や属性も確認します。

既存のブラウザ方式で保存したログイン情報は、そのままCookie方式として扱います。API設定とCookieは選択を切り替えても消しません。「保存した認証情報を消去する」は両方の認証情報が対象です。

期限切れ・ログイン制限・追加確認・通信失敗などで接続先を確認できなければ、以前のCookieは更新しません。確認中の設定変更・ルーム保管・アプリ終了・送信中の変更も保存を止めます。Cookie入力はチャットへ貼り付けず、この専用欄を使ってください。X側の制限を解除する機能ではありません。

#### Discordと通常会話の分離

Discord自動返信では、キャラ指示と同一チャンネルの会話を使い、通常会話の全履歴・記憶をそのまま渡しません。音声・動画の入力は対象外です。受信停止、定期自律OFF、自動返信OFFは別操作です。生成待ち/実行中の返信は中止できる場合があり、結果未確認は送信先を調べて確認済みを記録します。

#### Discordの送信先を選ぶ

1. ルーム内のBotトークン、利用許可、許可チャンネルを設定して保存します。
2. 「サーバー一覧を取得」で、このBotが参加するサーバーを取得します。
3. サーバーを選ぶとチャンネル一覧を取得します。未許可チャンネルは選択できません。必要なら先に上部の許可チャンネル設定を変更してください。
4. チャンネルを選ぶと、閲覧権限を持つメンバーを取得します。これはオンライン中/現在閲覧中の一覧ではありません。取得にはBot側のServer Members Intent等が必要な場合があります。
5. 宛先は「指定しない（チャンネルへの発言）」または1ユーザーを選べます。指定時はそのユーザーだけをメンションします。everyoneやroleの一括メンションは許可しません。
6. 本文と必要な画像を指定し、下書き作成後に送信先・宛先・内容を確認して承認します。候補取得や選択だけでは送信しません。

一覧が複数ページある場合は次ページを取得できます。ルーム変更時に候補と宛先を破棄します。権限・Intent不足やAPIエラーでは、取得できた範囲を全員の一覧として扱わないでください。

#### 入力中表示と本体会話への反映

自動返信の生成中は、Discordの入力中表示を定期更新します。完了/中止/失敗時に更新を止めますが、Discord側で表示が消えるまで短い時間がかかることがあります。入力中表示のAPI失敗は返信自体を失敗にせず、監査へ記録します。

新たに受信したメッセージと、送信成功が確認できたBotメッセージは、このルームの会話・会話ログにも保存します。本文にDiscord、チャンネルID、発言者を示し、DiscordメッセージIDで再受信/エコーの重複を防ぎます。本体画面は定期確認で反映するため、わずかな遅れがあります。生成・編集中は、その操作を終えてから画面を更新します。

添付だけの発言はファイル名を記録し、添付の自動ダウンロードや画像表示は行いません。既存の受信履歴の一括取り込みは行いません。送信結果が未確認の状態を送信成功とみなして発言を追加することもありません。

**本体/ブラウザでの会話をDiscordへ自動転送しません。** Discord自動返信の生成には従来どおり同じチャンネルの履歴を用い、本体の通常会話履歴を丸ごと送信しません。1ルーム1Bot・ルーム内の認証管理・ルーム横断の重複チェックは維持します。

#### Discordから画像生成を頼む

画像生成先を設定し、このルームの画像ツール権限で実行を許可すると、自動返信でも画像生成を利用できます。画像生成以外も、同じルームで利用可能・許可されているツールを使えます。生成結果を待ってから返答し、成功した保存IDの画像を最大4枚・既存の合計8MiB上限内で添付します。同じ画像は本体の会話にも表示します。ファイル名の推測は使いません。

画像生成中は、生成先の設定待機時間を考慮して待ちます。タイムアウト・失敗はAIへ結果として返し、その返信では追加生成しません。設定なし/権限なしでは画像生成を公開しません。自動返信許可・受信設定が失効した場合も新たなツール実行や送信を行いません。

#### Discordから記憶・場所・予約などのツールを使う

Discord返信も、ブラウザの通常会話と同じルームのツール定義・権限を使用します。必要なツールはAIが利用可能な機能から選びます。画像生成には接続先の設定と実行権限が必要です。利用できない機能や、設定されていない接続先は使えません。

操作の予告だけで正式な呼出がない場合は、具体的な依頼と予告が検知できたときに1回だけ続行を案内します。能力追加後の実ツール未使用にも既存の確認を行います。相談・例文・引用を無条件に操作へ変える仕組みではありません。

ツールを呼び、返ってきた結果を元に返答します。短期メモなどの更新案は人の保存まで未反映、外部送信の下書きは人の承認まで未送信です。「毎回確認」のツールはアプリ側の権限申請と承認を使い、Discordメッセージだけで承認・権限変更はしません。「禁止」のツールも使えません。

書き込み結果が結果未確認・一部完了などの場合は、その返信で同じ書き込みを繰り返さず状態を報告します。予約の登録や通知の受付は、予約時刻の実行・配信完了とは別です。ツール後にAIの回答生成が失敗した場合は、アプリがツール結果の状態を報告することがあります。

通常会話履歴や記憶を毎回まとめてDiscord返信へ渡す処理は追加していません。ただし、Discord側の依頼に応じてルーム内の記憶・知識をツールで参照した場合、その結果を返信に使用できます。送信元チャンネルの許可・ルームのツール権限を運用に合わせて設定してください。

#### 自動返信の上限に達したとき

日次上限が0以外で当日の応答枠を使い切った場合、自動返信の対象となる新しいメッセージへ、上限に達した旨と日本時間の翌日0:00にリセットされる旨を定型文で返信します。通知はAI生成やツール実行を行わず、日次の応答枠にも含めません。0の無制限設定では上限通知を出しません。通常の返信と同じく、利用許可・対象チャンネル・メンション/全発言の条件に従います。

同じ受信メッセージへ通知を重複送信せず、送信結果が未確認の場合も自動再送しません。停止・許可取り消し・日付変更等で条件が変わった通知は送信しません。通知は本体の会話にも保存し、モデル名はAIを使った応答と区別してAkari-Chatと表示します。

#### ブラウザ側の返信待ち・思考中表示

Discordの自動返信対象を受信すると、選択中ルームの会話欄に「Discordの返信待ち」を点滅表示します。生成・ツール処理中は「Discordへの応答を生成中」、送信中は「Discordへ送信中」と表示し、完了・失敗・中止で消えます。ブラウザは定期確認で状態を取得するため、表示には短い遅れがあります。

実際のDiscord返信生成中は、自動表情もthinking対象になります。画像がない場合の既存の代替表示や手動設定は維持します。別ルームや返信対象外の受信、上限の定型通知はAIの思考中として表示しません。表示用の点滅行はログへ保存せず、未送信の入力も保持します。

#### Discordのチャンネルと対話ユーザーの制限

メインチャンネルと追加許可チャンネルを合わせた範囲で、受信・参照・送信ができます。Botに対話できるのは「ユーザID」本人と「許可するユーザID」に登録した人だけです。「自動返信対象」の全発言設定でも、このユーザー制限は適用されます。日次上限のお知らせも対象ユーザーだけに返信します。

許可チャンネル内の他ユーザーの投稿は受信履歴・本体の会話に記録される場合がありますが、自動返信を開始せず、自動返信生成用の会話履歴にも含めません。Bot自身の過去発言は生成履歴に含みます。送信時の任意の宛先指定は別の操作で、対話許可リストを変更しません。

既存設定のチャンネル一覧は追加許可分として保持します。最初の項目をメインチャンネルへ自動変更しません。更新後はデフォルトのチャンネルIDと本人のユーザIDを明示して保存してください。利用許可ONでどちらかが未設定なら、受信・API操作・自動起動は開始できません。利用許可OFFのまま準備する場合は空欄でも保存できます。

#### 本体会話のDiscord表示

Discordからの受信は「【From: Discord / チャンネル名 】」、送信成功したBot発言は「【To: Discord / チャンネル名 】」を発言者名の右側に少し間隔を空け、名前と同じ書式で表示します。本文の先頭には重ねて表示しません。受信者の発言ラベルは、ルームの利用者ユーザIDと一致すればYOU、それ以外は発言者のユーザー名です。会話画面と会話ログに共通して適用します。

チャンネル名を取得できない場合は、チャンネルIDを代わりに表示します。名前が取得できないだけで、送受信が失敗することはありません。

#### Discordの応答が作れなかった場合

モデル呼出1回あたりの上限は10分です。ローカルモデルの通信読み取り待ちには別の120秒タイムアウトもあります。ツール待機は処理ごとの設定に従います。生成の時間超過・空応答・生成エラーは定型文で通知し、既に取得済みのツール結果はアプリから報告します。ツールやモデルを自動でやり直す処理ではありません。

利用者の中止や設定失効、モデルが明示的に返した[SILENCE]には通知を強制しません。Discord送信自体の結果が未確認の場合も再送せず、履歴と実際の送信先を確認してください。返信履歴で生成の終了理由と送信結果を確認してください。

### Gateway／Lite

このルームへのアクセス許可。共通側は「アプリ設定 → 外部連携」で準備します。

#### Gateway／Liteのルーム項目

| 項目 | 初期値 | 動作 |
| --- | --- | --- |
| このルームへのアクセス | OFF | 状態と直近会話履歴の取得を許可 |
| このルームでの会話 | OFF | Gateway経由の会話送信を許可。アクセス許可も必要 |
| 外部イベント保存 | OFF | Gatewayから届くイベントの保存を許可。アクセス許可も必要 |

共通Gatewayを起動してもルームへのアクセスは自動で許可されません。逆にルームを許可しても共通サーバーは自動で起動しません。

X/Discordは一つのルームで複数アカウント/Botを同時に扱いません。共通に複数登録して選ぶ構成でもありません。

## 設定・接続を確認する

1. ROOMとサービスを選び、必要な認証・接続情報を入力します。
2. このルームでの利用条件を確認して保存します。
3. 「接続確認・他ルームとの重複を確認」などの操作で、認証状態・権限・競合を確認します。
4. まず必要な参照を試し、対象アカウント・チャンネル・カレンダーを確認します。

他ルームに同じアカウント/Bot等が登録されていないかのチェックは、実際の利用先を確認するためのものです。警告が出たら登録内容を見直します。

## 送信するとき

参照、送信案の作成、確認後の実送信を区別します。送信先・本文・日時・添付・変更/削除対象を読み、画面の確認操作を行ってから実行します。案の作成成功は投稿や予定の登録成功ではありません。

Discordの自動返信は独立した初期OFF設定です。有効化すると、条件に合う受信へ個別確認なしで返信する経路があります。受信開始/停止、REST/Gateway、対象チャンネル、モデルの準備をそれぞれ確認します。

## エラー・結果未確認

通信断などで結果未確認になった場合は、実サービス側と履歴を確認します。重複送信を避けるため、確認前に同じ操作を繰り返さないでください。別PC・別Windowsユーザーへの移設後は認証の再登録が必要な場合があります。

URL監視は「ルーム設定」、Web検索/PDF取得や画像生成の共通接続は「アプリ設定 → Web・画像生成」です。DuckDuckGoをブラウザで使えても、アプリからは取得できない場合があります。

## アカウント・接続項目の詳細

画面は接続先に合わせて生成されます。認証欄の表示が空でも「保存済み」の状態表示があれば未登録とは限りません。

| 項目 | 意味・動作 | 初期状態・制約 |
| --- | --- | --- |
| このルームで利用を許可する | そのルームで対象サービスの参照・提案等を使えるようにします | 未設定は無効。設定保存と実認証成功は別 |
| 保存した認証情報を消去する | 対象接続の保存済み秘密を明示的に消去 | 消去後は再認証/再登録が必要 |

「設定を保存」は登録内容の保存です。「OAuth認証URLを作る」から接続先で許可した後、完了状態を確認します。XのCookie方式では、接続方式を選んで保存した後に「Cookieを取り込む」を使います。JSONを入力しただけでは保存しません。

「接続確認・他ルームとの重複を確認」は対象アカウントの実際のID等を取得して照合します。未確認のIDは重複なしと断定せず、保管中ルームも含む警告を確認します。重複チェックは他ルームの設定を書き換える操作ではありません。


外部送信用の画像は最大4枚・合計8MiB、取込時はPNG/JPEG/WebP・1枚5MiBまでです。通常会話への画像入力の合計上限12MiBとは別です。

「参照する／送信前の下書きを作る」は、選んだ操作によって参照または確認待ち案作成を行います。確認待ちカードの送信先・本文・添付を読んで「送信先と内容を確認しました」をチェックし、送信ボタンで確定します。却下は未送信案の処分で、送信済み投稿の取り消しではありません。
