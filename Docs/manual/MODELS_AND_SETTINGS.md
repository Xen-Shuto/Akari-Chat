# モデルの設定

2026年11月1日版。

[詳細マニュアルに戻る](MANUAL.md)

この設定は主に「共通設定 → アプリ設定」にあります。接続の継承は[共通設定](COMMON_SETTINGS.md)、ルームだけの変更は[ルーム別設定](ROOM_SETTINGS.md)を参照してください。

## ローカル会話モデルを使う

1. 会話用GGUFを `Models/LLM` 内に置きます。サブフォルダも再帰的に認識します。
2. 「アプリ設定 → 会話モデル」を開きます。
3. 「Models/LLM内のモデル」から選ぶか、「GGUFのパス」を入力します。
4. 「llama-server」を確認します。通常は `llama.cpp/llama-server.exe` です。
5. 必要に応じて画像・MTP、生成・メモリ設定を調整し、「設定を保存」を押します。
6. 「モデルを起動」を押し、準備完了を待ちます。

モデルや起動条件の変更後は、停止して再起動してください。モデル名が一覧に表示されることは、エンジンへの対応や読み込み成功の保証ではありません。

## mmprojとMTP

対応ファイルをモデルごとに同じフォルダへまとめる構成を推奨します。

```text
Models/LLM/
└─ 会話用モデル/
   ├─ model.gguf
   ├─ mmproj-model.gguf
   └─ mtp-model.gguf
```

ファイル名は構成例です。配布元が指定した対応ファイルを使ってください。

「mmproj・MTPを自動選択」が有効なら、名前やGGUFの情報から候補を探します。複数候補・対応不明の場合は未選択です。自動選択は動作・品質の確認を意味しません。

- **mmproj**：画像対応モデルで必要となる補助ファイル。対応する本体と組み合わせます。
- **MTP**：対応モデルで使う先読み機能。「使用しない」「本体に内蔵」「別ファイル」を選びます。本体内蔵なら別ファイルは不要です。
- **MTP先読み数**：初期値2は、最速値として保証された設定ではありません。

手動指定する場合は自動選択をオフにします。MTPはすべてのモデルで使える機能ではありません。

## 生成・メモリ設定

| 項目 | 調整の考え方 |
| --- | --- |
| コンテキスト | 指示・記憶・会話・生成の文脈範囲。モデルの対応範囲とメモリ容量に合わせます |
| GPUレイヤー | GPUへ載せる層数。大きくするとVRAM不足になる場合があります |
| Temperature | 出力のばらつきに関わる設定。モデルの推奨値を出発点にします |
| Top-P | 次に出す語の候補範囲に関わる設定 |
| 最大生成tokens | 空白・負数は0、小数は切り捨てて保存。0は会話の上限指定を省略しモデル/接続先に任せます |
| 思考モード（llama.cpp） | モデルに任せる/有効/無効。対応するローカルモデル・テンプレート用 |
| 送信する直近メッセージ数 | モデルに渡す最近の発言数。表示件数とは別です |
| 追加の起動引数 | JSON配列。例：`["--jinja"]` |

最大生成tokensを0にしても、モデルのコンテキストや接続先の上限は残ります。Anthropic APIでは取得済みモデル情報の出力上限を使用します。要約・自律処理などの専用上限は別です。思考モードは保存後に開始する生成へ反映し、外部APIには適用しません。

追加引数にモデルパスなどの管理済みオプションを重複指定できません。効果はモデルによって異なるため、一度に多数の項目を変えずに確認してください。

## 会話用の外部APIを使う

1. 「アプリ設定 → 会話モデル」を開きます。
2. 接続方式でGemini、OpenAI、Anthropic、OpenAI互換のいずれかを選びます。
3. APIキーとモデルIDを設定します。互換APIではベースURLも指定します。
4. 対応する接続先では「モデル一覧を取得」から選べます。モデルIDの手入力も可能です。
5. 「設定を保存」を押します。

各ルームの通常会話・再生成・グループ会話の標準接続になります。ルームだけ別の接続を使う場合は「ルーム設定 → 会話API」で共通設定に従う指定を外し、独自の接続を保存します。

画像入力・ツール呼び出しの能力はモデル情報から自動設定します。未知のモデルや実接続のエラーは表示を確認します。Temperature/Top-Pの送信は、対応モデルで必要な場合に有効にします。

接続設定は共通・ルームごとに方式別で保存します。接続方式を選び直すと、その方式の保存済みURL・モデル・キーを表示します。「設定を保存」で選んだ接続方式を適用します。

同じ接続でキーを空欄保存すると登録済みキーを保持します。削除には専用の消去指定を使います。別サービス・別URLへキーは自動継承しません。

保存済みのAPIキーは、設定画面のパスワード欄に実値を伏字で表示します。ダミーの伏字文字列をキーとして扱いません。表示した状態からモデル一覧を再取得できます。接続先を変更した場合は、元のキーを新しい接続先へ引き継がないよう入力欄をクリアします。「保存済みのキーを消去」を選んだ場合は、表示中の値を再登録せずに削除します。

**外部APIには会話本文・設定に従った記憶・選択画像などが送信されます。** 利用枠・料金は接続先に従います。失敗時の自動再送や他サービスへの自動切替は行いません。

手動・定期・行動予約の自律行動も、そのルームの会話API接続を使います。研究購読・会話後の記憶処理・夜間整理の文章生成も同じ会話API接続を使います。埋め込み・検索・索引はローカルの記憶検索モデルを使います。Discord自動返信など、今回の対応外の補助処理は引き続きローカル会話モデルが必要です。

## 記憶検索モデルを使う

1. EmbeddingGemma用GGUFを用意します。アプリは自動ダウンロードしません。
2. 「アプリ設定 → 記憶検索モデル」でGGUFを選んで保存すると、検索モデルが起動します。起動済みの場合は再起動します。
3. 対象ルームで「ルーム設定 → 記憶索引」から索引を作成・更新します。
4. 処理状態を確認し、「記憶・知識 → 検索」で意味検索を使います。

検索モデルは会話モデルとは別の管理プロセスでCPU上で動作します。標準では、ルームの自動検索が有効な場合に意味検索を使います。利用できなければキーワード検索へ切り替え、送信内訳に理由を残します。

標準では次回起動時にも検索モデルを起動します。共通設定では検索設定の保存・再起動とキャッシュ整理、ルーム設定では索引作成・更新を行います。

関連：[記憶と知識](MEMORY_AND_KNOWLEDGE.md)、[困ったとき](BACKUP_AND_TROUBLESHOOTING.md)

## 値の決め方と保存時の上限

通常会話の既定はコンテキスト8192、GPUレイヤー99、Temperature0.7、Top-P0.95、最大生成1024、履歴40、思考はモデルに任せる、自動起動ONです。各欄の範囲・設定が効く時点・MTP方式は[アプリ設定の項目表](main_tabs/APP_SETTINGS.md)を参照してください。

最大生成tokensは保存時に空白・負数を0、小数を切り捨てます。0〜32768の整数を保存し、0では通常会話の任意上限を省略します。Anthropicは必須の出力上限に取得済みモデル情報を用いる経路があります。文脈容量や接続先の実上限はなくなりません。

検索モデルはEmbeddingGemma方式、類似度0.45、自動起動OFF、自動意味検索OFFが既定です。語の前置形式等も方式に結び付くため、別系統のGGUFを単に指定して同等対応と解釈しません。

## 会話APIの保存先と能力

共通/ルーム別の接続はSQLiteで管理し、ルームが継承する場合は実行時に共通を解決します。キーはWindowsユーザー向け保護で保存する対象です。暗号化DB全体という意味ではありません。キーを空欄で保存すること、消去指定、別接続への変更を区別します。

画像・ツール対応はモデル情報と取得カタログで判断します。未知モデルの対応は確定できず、接続先が未対応として拒否する可能性があります。モデル一覧の取得成功と回答生成成功も別です。

## Geminiのモデル候補の初期表示

共通/ルーム別の接続方式がGeminiのとき、モデル一覧取得前から次の順で候補を表示します。

1. モデルを選択してください（未選択）
2. gemini-3.1-flash-lite
3. gemini-3.5-flash-lite
4. gemma-4-26b-a4b-it
5. gemma-4-31b-it

空のモデルを自動選択・保存する指定ではありません。保存済みのモデルIDは保持し、この4候補以外なら現在の指定として追加表示します。「モデル一覧を取得」の成功後は取得結果へ置き換えます。初期候補への掲載は、その認証での利用可否やモデルの画像/ツール対応を確認した意味ではありません。
