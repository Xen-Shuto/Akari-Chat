# モデルの設定

2026年10月31日版。

[ユーザーガイドに戻る](USER_GUIDE.md)

この設定は主に「共通設定 → アプリ設定」にあります。接続の継承は[共通設定](COMMON_SETTINGS.md)、ルームだけの変更は[ルーム別設定](ROOM_SETTINGS.md)を参照してください。

## ローカル会話モデルを使う

1. GGUFを `Models` 内に置きます。
2. 「アプリ設定 → 会話モデル」を開きます。
3. 「Models内のモデル」から選ぶか、「GGUFのパス」を入力します。
4. 「llama-server」を確認します。通常は `llama.cpp/llama-server.exe` です。
5. 必要に応じて画像・MTP、生成・メモリ設定を調整し、「設定を保存」を押します。
6. 「モデルを起動」を押し、準備完了を待ちます。

モデルや起動条件の変更後は、停止して再起動してください。モデル名が一覧に表示されることは、エンジンへの対応や読み込み成功の保証ではありません。

## mmprojとMTP

対応ファイルをモデルごとに同じフォルダへまとめる構成を推奨します。

```text
Models/
└─ 会話用モデル/
   ├─ model.gguf
   ├─ mmproj-model.gguf
   └─ mtp-model.gguf
```

ファイル名は構成例です。配布元が指定した対応ファイルを使ってください。

「mmproj・MTPを自動選択」が有効なら、名前やGGUFの情報から候補を探します。複数候補・対応不明の場合は未選択です。自動選択は動作・品質の確認を意味しません。

- **mmproj**：画像対応モデルで必要となる補助ファイル。対応する本体と組み合わせます。
- **MTP**：対応モデルで使う先読み機能。「使用しない」「本体に内蔵」「別ファイル」を選びます。本体内蔵なら別ファイルは不要です。
- **MTP先読み数**：初期値2は、最速値として保証された設定ではありません。

手動指定する場合は自動選択をオフにします。MTPはすべてのモデルで使える機能ではありません。

## 生成・メモリ設定

| 項目 | 調整の考え方 |
| --- | --- |
| コンテキスト | 指示・記憶・会話・生成の文脈範囲。モデルの対応範囲とメモリ容量に合わせます |
| GPUレイヤー | GPUへ載せる層数。大きくするとVRAM不足になる場合があります |
| Temperature | 出力のばらつきに関わる設定。モデルの推奨値を出発点にします |
| Top-P | 次に出す語の候補範囲に関わる設定 |
| 最大生成tokens | 空白・負数は0、小数は切り捨てて保存。0は会話の上限指定を省略しモデル/接続先に任せます |
| 思考モード（llama.cpp） | モデルに任せる/有効/無効。対応するローカルモデル・テンプレート用 |
| 送信する直近メッセージ数 | モデルに渡す最近の発言数。表示件数とは別です |
| 追加の起動引数 | JSON配列。例：`["--jinja"]` |

最大生成tokensを0にしても、モデルのコンテキストや接続先の上限は残ります。Anthropic APIでは取得済みモデル情報の出力上限を使用します。要約・自律処理などの専用上限は別です。思考モードは保存後に開始する生成へ反映し、外部APIには適用しません。

追加引数にモデルパスなどの管理済みオプションを重複指定できません。効果はモデルによって異なるため、一度に多数の項目を変えずに確認してください。

## 会話用の外部APIを使う

1. 「アプリ設定 → 会話API」を開きます。
2. 接続方式でGemini、OpenAI、Anthropic、OpenAI互換のいずれかを選びます。
3. APIキーとモデルIDを設定します。互換APIではベースURLも指定します。
4. 対応する接続先では「モデル一覧を取得」から選べます。モデルIDの手入力も可能です。
5. 「共通の接続を保存」を押します。

各ルームの通常会話・再生成・グループ会話の標準接続になります。ルームだけ別の接続を使う場合は「ルーム設定 → 会話API」で共通設定に従う指定を外し、独自の接続を保存します。

画像入力・ツール呼び出しの能力はモデル情報から自動設定します。未知のモデルや実接続のエラーは表示を確認します。Temperature/Top-Pの送信は、対応モデルで必要な場合に有効にします。

同じ接続でキーを空欄保存すると登録済みキーを保持します。削除には専用の消去指定を使います。別サービス・別URLへキーは自動継承しません。

**外部APIには会話本文・設定に従った記憶・選択画像などが送信されます。** 利用枠・料金は接続先に従います。失敗時の自動再送や他サービスへの自動切替は行いません。

会話APIを変更しても、自律行動・Discord自動返信・記憶整理などの背景／補助生成は外部APIへ切り替わりません。これらにはローカル会話モデルも準備してください。

## 記憶検索モデルを使う

1. EmbeddingGemma用GGUFを用意します。アプリは自動ダウンロードしません。
2. 「アプリ設定 → 記憶検索モデル」でパスと類似度の下限を設定し、保存します。
3. 対象ルームで「ルーム設定 → 記憶索引」から索引を作成・更新します。
4. 処理状態を確認し、「記憶・知識 → 検索」で意味検索を使います。

検索モデルは会話モデルとは別の管理プロセスでCPU上で動作します。「自動想起で意味検索を使う」は、ルームの自動検索が有効な場合に適用します。利用できなければキーワード検索へ切り替え、送信内訳に理由を残します。

「次回起動時に検索モデルも起動」と、ルームの「保存後の索引更新」は別設定です。共通設定ではモデルの停止・キャッシュ整理、ルーム設定では索引作成・更新を行います。
