# 共通設定の使い方

2026年10月31日版。

[ユーザーガイド](USER_GUIDE.md) / [ルーム別設定](ROOM_SETTINGS.md)

右ペインの「共通設定」には、グループ会話・共有データ・ルーム管理・アプリ設定があります。ここにある操作が、すべてのルームを一括変更するという意味ではありません。

## どこまで共通なのか

| 機能 | 共通側 | ルーム側 |
| --- | --- | --- |
| ローカル会話モデル | GGUF・llama.cpp・起動条件・生成設定 | 会話APIで共通接続の継承/独自接続を選択 |
| 会話API | 通常の接続先・キー・モデル | このルームだけ別の接続へ上書き可能 |
| 記憶検索モデル | 検索用GGUF・起動/停止 | 自分の資料の索引・自動想起・検索方針 |
| 外観 | 全体の基本テーマ・フォント等 | 項目ごとに共通を使う/上書きを選択 |
| 音楽検索 | 推薦リンクを作るサービス | 会話内で推薦を依頼 |
| Web・画像生成 | 接続先・認証・共通条件 | ツールの許可、監視URL、生成・利用対象 |
| Googleカレンダー | 認証用の接続情報 | 利用許可・カレンダーID・操作 |
| X / Twitter・Discord | 共通アカウント登録はしない | ルーム内でアカウント/Botを登録・認証 |
| Gateway／Lite | サーバー・ポート・HTTPS・トークン | 接続できるルームと操作の許可 |

会話APIはルームの独自設定が優先です。外観は上書きした項目だけルームを優先します。ルーム側の「共通を使う」を残せば、共通側の変更に追従します。

## アプリ設定

### 会話モデル

ローカルllama.cpp用の設定です。まずGGUFとllama-serverの場所を指定して保存し、「モデルを起動」を押します。

- mmproj・MTPは対応する本体と組み合わせます。自動選択の結果を確認してください。
- モデルの自動起動を保存すると、次回は起動バッチだけでモデルの準備も始まります。
- コンテキスト/GPUレイヤーなど起動条件を変更した場合は、モデルを停止して起動し直します。
- Temperature、Top-P、最大生成tokens、送信履歴数は生成に関わる設定です。
- 最大生成tokensの0はアプリからの上限指定を省く扱いです。モデル/APIの上限までなくなるわけではありません。
- 「思考モード（llama.cpp）」はモデルに任せる/有効/無効。対応するローカルモデル向けで、外部API用の設定ではありません。

詳しい選び方・設定順は[モデルの設定](MODELS_AND_SETTINGS.md)を参照してください。

### 会話API

1. Gemini API / OpenAI API / Anthropic API / OpenAI互換 APIから選びます。
2. 接続先・APIキーを設定します。OpenAI互換ではベースURLも確認します。
3. 「モデル一覧を取得」から選ぶかモデルIDを入力します。
4. 「共通の接続を保存」を押します。

共通を継承するルームに適用されます。独自接続のルームは変更されません。画像入力とツール呼び出しの対応はモデル情報から自動設定しますが、未知のモデルの実動作を保証する判定ではありません。

同じ接続のキーを空欄で保存すると登録済みキーを保持します。削除は専用の消去指定を使います。外部APIでは会話・設定された記憶・添付等を送信し、接続先の利用料金/制限に従います。

通常会話・再生成・グループの各話者・キャラ作成補助は会話接続を使います。自律・夜間整理などの背景生成まで一括で外部APIへ切り替える設定ではありません。

### 記憶検索モデル

会話モデルと別に、EmbeddingGemma用GGUFを用意してパスを保存します。アプリが勝手にモデルをダウンロードする機能ではありません。

1. モデルを設定し、検索モデルを起動します。
2. 対象ルームの「ルーム設定 → 記憶索引」を作成/更新します。
3. 「記憶・知識 → 検索」で意味検索を確認します。

「次回起動時に検索モデルも起動」「自動想起で意味検索を使う」と、ルーム側の「保存後の索引更新」は別設定です。モデル本体は共通でも、索引の対象はルーム別です。

採用しているGGUFの入手先：[EmbeddingGemma 300M QAT Q4_0](https://huggingface.co/ggml-org/embeddinggemma-300M-qat-q4_0-GGUF)。検索モデルを変更したら索引も作り直します。

### 音楽検索

YouTubeは常に有効。Bandcamp、SoundCloud、Spotify（要登録）をチェックで選び、保存します。これは推薦用の検索リンクを作る設定で、アプリ内再生やログインを代行するものではありません。

### 外部連携 / Web・画像生成

「外部連携」にはGoogleの認証とGatewayの共通基盤があります。X/Discordのアカウントはここでは登録せず、対象ルームの「外部接続」で完結させます。

「Web・画像生成」では検索・画像生成の接続先を設定します。画像生成は会話モデルと別で、SD WebUI/Forgeを使う場合は対応する画像生成サーバーも起動してください。認証や接続テスト、送信先は[外部接続ガイド](TOOLS_AND_CONNECTIONS.md)で確認できます。

### 動作の確認 / 外観

「動作の確認」で起動ログ・生成計測・ツール履歴などを確認します。AIが「保存した」と話しただけでなく、実際のツール結果と保存状態を確認できます。

「外観」でテーマ、アクセント、UI/会話フォント、サイズ、行間を選んで保存します。ルーム側で上書きしていない項目の基本値になります。

## ルーム管理

全ルームの作成・保管・復元・取込・書出しを行う入口です。**操作対象は「管理するルーム」で選んだルーム**です。右のROOMとは別に選べます。

「キャラ作成」は設定補助・試し会話から新規キャラを作る機能。「キャラ取込」はroom_config.jsonを基準に既存フォルダをコピーする機能です。作成・取込の違いと初期ログは[ルームと会話](ROOMS_AND_CHAT.md)、[最初のメッセージ](FIRST_MESSAGE.md)を参照してください。

## 共有データ

- 共有手順：全ルーム向けの手順資料。ルームへコピーした後は独立した下書きで、自動同期しません。
- 共通クローゼット：共通使用を選んだルーム間でユーザーの外見・衣装・着用状態を共有します。共通使用中の編集は他の利用ルームにも影響します。キャラ側の衣装や画像の関連付けは別です。

共通へ保存する前に、特定キャラの秘密や関係まで共有する内容になっていないか確認します。

## グループ会話

共通メニューからグループを作り、参加ルームと順番を選びます。履歴はグループ専用で、個別ルームの会話とは別です。各話者の会話API設定を使います。操作手順は[ルームと会話](ROOMS_AND_CHAT.md)にまとめています。

メインタブ単位の操作案内は[メインタブ別ガイド](USER_GUIDE.md#メインタブ別ガイド)をご覧ください。
